<objective>
Author the six per-entity row processors and the chunked-savepoint
orchestrator that drives them. Each row processor consumes one parsed row,
invokes the appropriate Phase 04.1 `UpsertXByCode` query inside a
per-row SAVEPOINT, and emits either a `succeededRow` or a `*rowError`. The
chunk orchestrator opens one outer Tx per 50-row chunk, resolves skill
codes once for the chunk, runs the per-row savepoints, commits the outer
Tx, and runs POST-COMMIT cache invalidation.

This wave intentionally does NOT touch the top-level handler entry points
(`BulkImportCatalog`, `GetImportJob`) — that wiring lands in Plan 05-06.
The deliverable here is the compiling, unit-testable row+chunk core.

Output: 7 source files + 7 paired test files in
`services/api/internal/imports/`. Integration-level tests run against
testcontainers Postgres + miniredis; pure-unit tests use mocks.
</objective>

         a) `outerTx, err := s.deps.OrgDB.BeginTx(ctx)` — outer pgx Tx. On err: mark every row in chunk as failed with reason `tx_begin_failed`; return.

         d) Loop `for _, r := range rows`:

            - `out, procErr := rowProc.process(ctx, sp, orgID, r, resolver)`.
            - On procErr != nil: `_ = sp.Rollback(ctx)` (ROLLBACK TO); append failed; continue.
            - On success: `if err := sp.Commit(ctx); err != nil` (RELEASE) — append failed with reason `savepoint_commit_failed`; continue.
            - Else: `succeeded = append(succeeded, out)`.
         e) `if err := outerTx.Commit(ctx); err != nil` — chunk commit failure. Transfer ALL `succeeded` rows into `failed[]` with reason `chunk_commit_failed`; return `(nil, failed)`.
