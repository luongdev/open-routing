    ```go
    package middleware

    import (
        "encoding/json"
        "log/slog"
        "net/http"
    )

    // errorBody is the canonical error response shape (Shared Pattern S3).
    // Never leak stack traces. `error` is a stable identifier (machine-readable);
    // `reason` is a human-readable / debugging detail.
    type errorBody struct {
        Error  string `json:"error"`
        Reason string `json:"reason"`
    }

    // WriteError writes a JSON error response with the canonical shape.
    // Status is the HTTP status; code is the stable error identifier
    // (e.g., "invalid_org_id"); reason is the contextual detail
    // (e.g., "missing_header").
    func WriteError(w http.ResponseWriter, status int, code, reason string) {
        w.Header().Set("Content-Type", "application/json")
        w.WriteHeader(status)
        if err := json.NewEncoder(w).Encode(errorBody{Error: code, Reason: reason}); err != nil {
            slog.Error("httputil: encode error response", "err", err)
        }
    }

    // WriteJSON writes a JSON success response with the given body. Used by
    // handlers (Plan 06) for 200/201 responses.
    func WriteJSON(w http.ResponseWriter, status int, body any) {
        w.Header().Set("Content-Type", "application/json")
        w.WriteHeader(status)
        if err := json.NewEncoder(w).Encode(body); err != nil {
            slog.Error("httputil: encode json response", "err", err)
        }
    }
    ```

    Per Pattern S3: `error` and `reason` are the ONLY two keys. Future error shapes (e.g., `field` for validation errors) can extend this struct in a non-breaking way. Phase 5's bulk import endpoints add a `failed: [{row, field, message}]` shape — extending the body via a separate struct, not by modifying errorBody.

    Per ASVS V14.4 / V7.1.2: never leak stack traces. The slog.Error fallback above logs the encode failure but does NOT write the underlying error to the response body — the client sees `{}` (empty body after WriteHeader is already sent), which is acceptable because reaching this branch indicates a programming error or out-of-memory condition, not a normal failure.

    Step 1 — Create `services/api/internal/middleware/requestid.go`. Per PATTERNS.md L7 lines 474-490, this is a thin wrapper that mints a UUIDv7 per request, stores it in ctx via a typed key, and echoes the value via the `X-Request-Id` response header.

    ```go
    package middleware

    import (
        "context"
        "net/http"

        "github.com/google/uuid"
    )

    // requestIDCtxKey is the canonical key for the per-request UUIDv7 id.
    // Unexported empty struct prevents collisions (S1).
    type requestIDCtxKey struct{}

    // RequestID generates a UUIDv7 per request, stores it in ctx, and echoes it
    // via the X-Request-Id response header. chi's default RequestID middleware
    // uses a non-UUID atomic counter — D-28 mandates UUIDv7 for cross-system
    // correlation, so we ship our own.
    func RequestID(next http.Handler) http.Handler {
        return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
            id := uuid.Must(uuid.NewV7())
            ctx := context.WithValue(r.Context(), requestIDCtxKey{}, id)
            w.Header().Set("X-Request-Id", id.String())
            next.ServeHTTP(w, r.WithContext(ctx))
        })
    }

    // RequestIDFromContext returns the per-request UUIDv7 stored by RequestID
    // middleware. Returns false if ctx does not carry one (pre-middleware code
    // paths or test code that bypasses the middleware).
    func RequestIDFromContext(ctx context.Context) (uuid.UUID, bool) {
        id, ok := ctx.Value(requestIDCtxKey{}).(uuid.UUID)
        return id, ok
    }
    ```

    Notes:
    - The X-Request-Id header is set BEFORE next.ServeHTTP runs. This guarantees the header is on the response even if downstream handlers fail to write a body.
    - Per Research §"Don't Hand-Roll" line 980: do not reimplement UUID v7. Use `uuid.NewV7()` from `github.com/google/uuid` v1.6+.
    - `uuid.Must(uuid.NewV7())` panics only on entropy exhaustion (effectively never). If panic occurs, the chi `Recoverer` middleware (registered ahead of RequestID in Plan 06) catches it and emits 500 — acceptable failure mode.

    Step 1 — Create `services/api/internal/middleware/orgcontext.go`. This is the trust boundary where the API parses an external-supplied `X-Org-Id` header. After this middleware, every downstream code path treats ctx-stored `uuid.UUID` as authoritative.

    Per Research §Pattern 1 with the orgkey import swap (Plan 03 §import_cycle_note):
    ```go
    package middleware

    import (
        "net/http"

        "github.com/google/uuid"
        "go.opentelemetry.io/otel/attribute"
        "go.opentelemetry.io/otel/trace"

        "github.com/luongdev/open-routing/services/api/internal/db/orgkey"
    )

    // OrgContext middleware:
    //   1. Read X-Org-Id header
    //   2. Reject missing header with 400 invalid_org_id + missing_header
    //   3. Parse as UUID; reject parse failure with 400 + malformed_uuid
    //   4. Assert Version() >= 7 (D-19, D-20); reject older versions with 400 + uuidv7_required
    //   5. Store as uuid.UUID in ctx via orgkey.SetOrgID
    //   6. Inject org_id attribute on the active OTel span (FOUND-07)
    //   7. Call next handler with the new ctx
    //
    // This middleware is registered ONLY inside the /v1 sub-router (Plan 06).
    // Bypass paths (/healthz, /readyz, /metrics) per D-21 do not run through it.
    func OrgContext(next http.Handler) http.Handler {
        return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
            raw := r.Header.Get("X-Org-Id")
            if raw == "" {
                WriteError(w, http.StatusBadRequest, "invalid_org_id", "missing_header")
                return
            }
            id, err := uuid.Parse(raw)
            if err != nil {
                WriteError(w, http.StatusBadRequest, "invalid_org_id", "malformed_uuid")
                return
            }
            if id.Version() < 7 {
                WriteError(w, http.StatusBadRequest, "invalid_org_id", "uuidv7_required")
                return
            }

            ctx := orgkey.SetOrgID(r.Context(), id)

            // Inject org_id on the active OTel span (FOUND-07). The span exists
            // because otelhttp.NewHandler wraps the chi mux (Plan 06); this call
            // attaches the attribute to that span before next.ServeHTTP runs.
            // Per Pitfall 5 line 1046: SetAttributes works as long as the
            // attribute is added BEFORE the span ends, which is guaranteed by
            // calling here before next.ServeHTTP.
            span := trace.SpanFromContext(ctx)
            if span != nil {
                span.SetAttributes(attribute.String("org_id", id.String()))
            }

            next.ServeHTTP(w, r.WithContext(ctx))
        })
    }
    ```

    The three rejection paths and their JSON bodies are LOCKED by D-20 and FOUND-03. Do NOT consolidate the three reasons into a generic "bad request" — clients (and Phase 6's admin UI) rely on the specific reason string.
