1. A concrete code excerpt already verified in `01-RESEARCH.md` (referenced as **Research §{section}**)

### L5 — orgDB wrapper

#### `services/api/internal/db/pool.go` (pgxpool factory)

**Reference:** No Research example, but D-26 requires retry-with-backoff until Postgres healthcheck passes.
**External analog:** [pkg.go.dev/github.com/jackc/pgx/v5/pgxpool §New](https://pkg.go.dev/github.com/jackc/pgx/v5/pgxpool#New).

**Pattern:**
```go
func NewPool(ctx context.Context, dsn string) (*pgxpool.Pool, error) {
    cfg, err := pgxpool.ParseConfig(dsn)
    if err != nil { return nil, err }
    // Optional: set cfg.MaxConns from env or default 20
    var pool *pgxpool.Pool
    backoff := time.Second
    for i := 0; i < 10; i++ {
        pool, err = pgxpool.NewWithConfig(ctx, cfg)
        if err == nil {
            if perr := pool.Ping(ctx); perr == nil { return pool, nil }
            pool.Close()
        }
        time.Sleep(backoff)
        backoff = min(backoff*2, 10*time.Second)
    }
    return nil, fmt.Errorf("pgxpool init: %w", err)
}
```
- Backoff matches D-26 "API connection pool retries with backoff until healthy."

#### `services/api/internal/db/orgdb.go` (orgDB wrapper)

**Reference:** Research §"Pattern 2: orgDB wrapper implementing the sqlc DBTX interface" — copy nearly verbatim; Research §"Example 1: sqlc DBTX interface signature" for the exact method signatures.

**Key copy points (Research §Pattern 2, lines 486-575):**

**Compile-time guarantee:** Add `var _ generated.DBTX = (*OrgDB)(nil)` to assert the interface match at build time (after sqlc generation lands).

#### `services/api/internal/db/sqlcheck.go` (SQL inspector)

**Reference:** Research §"Pitfall 2: orgDB SQL inspection misses joined `org_id` references" (lines 1012-1020) — the correctness checklist.
**External analog:** [github.com/pganalyze/pg_query_go](https://github.com/pganalyze/pg_query_go) §"Parse" API.

**Key design points:**
- `SQLChecker` struct with `cache map[string]error` keyed by SHA-256 of SQL string (D-02 caching).
- `MustContainOrgFilter(sql string) error`: hash sql → lookup cache → on miss, call `pg_query.Parse(sql)`, walk the parse tree.
- Walking rules per Pitfall 2:
  - Statement type from AST root: only validate DML (SELECT/INSERT/UPDATE/DELETE); accept all DDL (CREATE/ALTER/DROP) but log a debug event (DDL should be in bypass path anyway).
  - For SELECT/UPDATE/DELETE: walk every nested `WhereClause` (including those inside JoinExpr `ON` clauses) and find at least one `ColumnRef` named `org_id` in a comparison (`A_Expr` with op `=` or `IN`).
  - For INSERT: walk `InsertStmt.Cols` — at least one target column named `org_id`.

```go
type requestIDCtxKey struct{}

func RequestID(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        id := uuid.Must(uuid.NewV7())
        ctx := context.WithValue(r.Context(), requestIDCtxKey{}, id)
        w.Header().Set("X-Request-Id", id.String())
        next.ServeHTTP(w, r.WithContext(ctx))
    })
}

func RequestIDFromContext(ctx context.Context) (uuid.UUID, bool) {
    id, ok := ctx.Value(requestIDCtxKey{}).(uuid.UUID)
    return id, ok
}
```

```go
func (h *handler) create(w http.ResponseWriter, r *http.Request) {
    ctx := r.Context()
    orgID, _ := middleware.OrgIDFromContext(ctx) // guaranteed by OrgContext middleware
    var body struct{ ExternalID, Name string }
```

## Shared Patterns (Cross-Cutting)

### Pattern S1: Context-key isolation

**Applies to:** every middleware (`orgcontext.go`, `requestid.go`, `db/bypass.go`) and every handler that reads request-scoped values.
**Reference:** Research §Pattern 1, lines 433-446 (`type orgIDCtxKey struct{}`).

**Rule:** Always use an unexported empty struct type as the context key. Never use a string. Provides compile-time collision safety and makes the key unreachable from outside the defining package.

```go
type orgIDCtxKey struct{}
type requestIDCtxKey struct{}
type bypassCtxKey struct{}
```

### Pattern S2: UUIDv7 everywhere

**Applies to:** every place an ID is minted (org_id, request_id, scaffold.id) — D-19, D-20, D-28.
**Reference:** Research §State of the Art §"uuid v4 → uuid v7"; D-19.

**Rule:**
- Minting: `uuid.Must(uuid.NewV7())` — never `uuid.New()` (which is v4).
- Parsing: `uuid.Parse(s)` returns `uuid.UUID`. Always check `id.Version() >= 7` before trusting it.
- Storage in context: store `uuid.UUID`, never `string`.

### Pattern S3: Structured JSON error responses

**Applies to:** every middleware error path and every handler error path.
**Reference:** Research §Pattern 1, line 453+ (`writeError(w, http.StatusBadRequest, "invalid_org_id", "missing_header")`); ASVS V7.

**Rule:** Body shape `{"error": "<code>", "reason": "<detail>"}`. Never leak stack traces. Codes are stable identifiers (e.g., `invalid_org_id`, `not_found`); reasons are debugging detail.

**Shared helper:** `writeError(w http.ResponseWriter, status int, code, reason string)` — define once in `internal/server/http_util.go` or per-package.

### Pattern S4: slog with structured fields

**Applies to:** every log emission across all packages.
**Reference:** Research §Example 4 (TracingHandler) + Research §Pattern 2 line 553-558 (slog.Warn for bypass).

**Rule:** Always use the global `slog.Default()` (set up in cmd/api/main.go). Pass structured key-value pairs as varargs: `slog.WarnContext(ctx, "message", "key1", value1, "key2", value2, ...)`. Never use `fmt.Println` or `log.Printf`. The TracingHandler auto-injects `trace_id`, `span_id`, `org_id`, `request_id` — handlers add domain-specific fields.

**Required event field for bypass events** (D-05): `event=orgdb_bypass`, `caller`, `reason`, `sql_hash`, plus any `org_id_attempted` if extractable.

### Pattern S5: OTel span attribute injection

**Applies to:** anywhere a request-scoped attribute should appear on the active span.
**Reference:** Research §Pattern 1, lines 468-470.

**Rule:** `trace.SpanFromContext(ctx).SetAttributes(attribute.String("key", value))`. Always inside a middleware or handler that has access to the request ctx. Span attributes for `org_id` MUST be set inside the OrgContext middleware before `next.ServeHTTP` to land on the right span.

### Pattern S6: Pitfall 5 ordering — chi.Use before otelhttp.NewHandler

**Applies to:** `cmd/api/main.go` server construction.
**Reference:** Research §Pitfall 5 (lines 1042-1050).

**Rule:** Construction order is exactly:
1. `mux := chi.NewRouter()`
2. `mux.Use(...)` (Recoverer, RequestID, then per-subroute OrgContext)
3. Register routes (`mux.Get`, `mux.Route`)
4. `rootHandler := otelhttp.NewHandler(mux, "open-routing-api")`
5. `http.ListenAndServe(addr, rootHandler)`

Wrapping in any other order breaks span lineage or middleware execution.

### Pattern S7: sqlc query authoring with explicit `org_id`

**Applies to:** every `.sql` file under `internal/db/queries/`.
**Reference:** Research §Example 2 (lines 1117-1137).

**Rule:** Every DML query must include `org_id` in WHERE clause (SELECT/UPDATE/DELETE) or in column list (INSERT). The orgDB validator rejects anything else. Phase 3 will follow this rule for all 6 catalog entities.

### Pattern S8: Test isolation via fresh UUIDv7

**Applies to:** every integration test that needs an org_id.
**Reference:** Pitfall 6 (Research §lines 1052-1060); FOUND-08 spec.

**Rule:** Mint a fresh `uuid.Must(uuid.NewV7())` at the top of every test function. Never declare a package-level `var defaultOrgID = uuid.MustParse(...)`. Tests `t.Parallel()` safely because their org_ids never collide.

### Pattern S9: Compile-time interface assertion for orgDB

**Applies to:** `internal/db/orgdb.go`.
**Reference:** Research §Example 1 (DBTX interface signatures).

**Rule:** Add `var _ generated.DBTX = (*OrgDB)(nil)` at the bottom of `orgdb.go` (after sqlc has generated `internal/db/generated/db.go`). This causes a compile error if the signatures drift. Apply the same pattern for any future wrapper.

### Pattern S10: pg_isready / redis-cli ping for healthchecks

**Applies to:** `docker-compose.yml` (S10a) and `/readyz` handler (S10b).
**Reference:** Research §Pattern 6 (docker-compose); Research §Example 6 (`/readyz`).

**Rule:**
- Compose: `test: ["CMD-SHELL", "pg_isready -U openrouting -d openrouting"]` for postgres; `test: ["CMD", "redis-cli", "ping"]` for redis.
- `/readyz`: `pool.Ping(ctx)` + `rdb.Ping(ctx).Err()` + `schema_migrations` row read + `dirty` flag check; 503 on any failure.
