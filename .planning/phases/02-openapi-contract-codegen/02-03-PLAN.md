<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| spec→codegen | `openapi/openapi.yaml` is the authoritative input; oapi-codegen translates it into Go types and an interface. |
| codegen→repo | Generated files are committed to git; drift gate (Plan 06) re-runs codegen in CI to detect drift. |
| dev→`go install` (`go generate`) | `go generate` fetches and runs the oapi-codegen binary from the module cache; tools.go pins it to a specific version. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-SC | Tampering (Supply Chain) | `github.com/oapi-codegen/oapi-codegen/v2` module fetched by `go install` | mitigate | oapi-codegen v2 is an established, widely-used Go codegen tool (DeepMap origin, now community-maintained). tools.go blank-imports it (build-tag isolated). Pinned to a specific minor version in go.mod via `go.mod require` line — version drift requires an explicit `go get`. Verified upstream at https://github.com/oapi-codegen/oapi-codegen. No `[ASSUMED]` or `[SUS]` classification per the planning_context — module is in the locked stack per Phase 1 D-43, D-22 and PROJECT.md (`OpenAPI 3.1 → oapi-codegen`). |
| T-02-SC-02 | Tampering (Generated Output Injection) | `services/api/internal/api/*.gen.go` | mitigate | Generated code is committed and reviewed in PR; reviewer scans the diff for any template-injected `eval`, `exec`, `os.Setenv`, network calls, or unexpected `unsafe.*` usage. oapi-codegen produces deterministic output from a YAML schema — no user-controlled strings reach Go code paths beyond schema field names + descriptions. Document one-line review check in SUMMARY: "Scanned generated server.gen.go for: eval, exec, os/exec import — none found." |
| T-02-DOS-01 | Denial of Service | `go generate` invocation in CI | accept | Codegen runtime is ~5-10s for a v0.1-size spec; CI lane budget is generous. No mitigation needed in v0.1. |
| T-02-INF-01 | Information Disclosure | spec.gen.go embedded bytes | accept | The spec is the same bytes served at `/openapi.yaml` (D-45, Plan 04). Embedding them in the binary is the desired behavior (D-45 rationale: spec matches running binary). |
</threat_model>
