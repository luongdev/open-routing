Exact YAML to add (paste verbatim — indentation is significant):

```yaml
  codegen-drift:
    # Phase 2 D-47 + D-48 + CONTRACT-04: spec lint (Redocly recommended) then
    # full codegen (sqlc + oapi-codegen + openapi-typescript) then a
    # git-diff-exit-code gate. Drift fails the PR with its own red check
    # (separate from go-test / web-typecheck so cause is immediately visible).
    #
    # Steps order (LOCKED by D-48):
    #   1. checkout
    #   2. setup-go + setup-node (parallel installs, no DAG savings here but
    #      keeps the job self-contained — D-47 explicit requirement)
    #   3. pnpm install (frozen-lockfile)
    #   4. Redocly lint openapi.yaml — BEFORE codegen (D-48). Spec must be
    #      valid before regen.
    #   5. install task CLI (same pin as compose-config)
    #   6. task gen — runs sqlc + go generate ./... + pnpm -F @open-routing/ui gen:api
    #   7. git diff --exit-code — any drift fails the job
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      # Go side: oapi-codegen via `go generate ./...`
      - uses: actions/setup-go@v5
        with:
          go-version-file: services/api/go.mod
          cache-dependency-path: services/api/go.sum
      # Node side: openapi-typescript + Redocly CLI (npx-invoked, no
      # package.json dep — D-48)
      - uses: pnpm/action-setup@v4
        with:
          version: 10
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm
          cache-dependency-path: web/pnpm-lock.yaml
      - name: pnpm install
        working-directory: web
        run: pnpm install --frozen-lockfile
      # D-48: Redocly lint BEFORE codegen. Pinned to a specific version
      # (NEVER @latest, per ASVS V14.3 comment at top of file).
      - name: redocly lint openapi.yaml
        run: npx --yes @redocly/cli@1.25.0 lint openapi/openapi.yaml --extends recommended
      - name: install task CLI
        run: go install github.com/go-task/task/v3/cmd/task@v3.40.0
      # D-47: run codegen via the canonical entry point so the CI behavior
      # matches local `task gen`. Sqlc is part of the chain too — sqlc on
      # the Phase 1 surface should be a no-op, but running it keeps the
      # full pipeline exercised.
      - name: task gen
        run: $(go env GOPATH)/bin/task gen
      # D-47: any diff means the committed generated code does not match
      # what the spec produces.
      - name: git diff codegen output
        run: |
          git diff --exit-code -- services/api/internal/api/ web/packages/ui/src/api/generated.ts
```

NOTES on each line:
- `runs-on: ubuntu-latest` matches every other job's runner.
- `actions/checkout@v4` matches all existing job pins.

- `cache-dependency-path: services/api/go.sum` — matches go-vet/go-lint/go-test; migration-drift omits this (it doesn't cache); we include it because codegen pulls the oapi-codegen module and caching go.sum saves ~30s per run.
- `pnpm/action-setup@v4` with `version: 10` matches web-typecheck/web-lint.
- `actions/setup-node@v4` with `node-version: 22` + `cache: pnpm` matches web-typecheck/web-lint.
- `pnpm install --frozen-lockfile` is the workspace-rooted install matching the existing pattern (working-directory: web).
- The Redocly invocation: `npx --yes @redocly/cli@1.25.0 lint openapi/openapi.yaml --extends recommended`. The `--yes` flag skips the "install this package?" prompt (npx defaults to interactive in CI). Pin to `@1.25.0` (Redocly CLI's current stable line). If a newer minor lands during execution, pin to the latest stable 1.x release at execution time — record the exact pin in the SUMMARY.
- `go install github.com/go-task/task/v3/cmd/task@v3.40.0` matches compose-config's `install task` step verbatim.
- `task gen` runs the locked target which after Plans 03 + 05 contains: `sqlc generate`, `go generate ./internal/api/...`, `pnpm -F @open-routing/ui gen:api`. The `$(go env GOPATH)/bin/task` invocation matches compose-config's task call.
- `git diff --exit-code -- services/api/internal/api/ web/packages/ui/src/api/generated.ts` paths match the exact directories owned by the codegen output (D-42: `services/api/internal/api/` per Pattern S1; D-40: `web/packages/ui/src/api/generated.ts`).

- This plan runs after all three; the drift gate will be green on a clean tree because the generated files match.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI runner→npm | The `npx @redocly/cli@1.25.0` invocation downloads the Redocly CLI on every run. |
| CI runner→`go install` | The `go install task` step downloads the task binary on every run. |
| CI runner→`pnpm install` | The frozen-lockfile install pulls registered npm dependencies from the lockfile. |
| git→PR merge | The drift gate is enforced via the github branch protection check; a passing job is the merge gate. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-SC-CLI | Tampering (CLI Supply Chain) | `@redocly/cli@1.25.0` via npx | mitigate | Pinned to a specific version (NEVER @latest, per the ci.yml file top comment). Verified at https://www.npmjs.com/package/@redocly/cli — official Redocly Inc. publisher. [TRUSTED] per the Package Legitimacy Audit pattern. v0.2 hardening: vendor Redocly CLI as a pnpm devDep with locked hash to remove the npx fetch step. |
| T-02-SC-TASK | Tampering (Supply Chain) | `go install github.com/go-task/task/v3/cmd/task@v3.40.0` | accept | Pin matches the existing `compose-config` job's pin exactly; if compose-config is acceptable, so is this. Both reach the same module proxy with the same proxy verification. |
| T-02-DOS-CI | Denial of Service | Long-running CI job | accept | Estimated runtime: ~3-4 min (1 min setup, 30s Redocly lint, 1 min task gen on a v0.1-size spec, 5s git diff). Comparable to other CI jobs. |
| T-02-EX-DRIFT | Elevation of Privilege via undetected drift | committed `*.gen.go` / `generated.ts` differs from spec | mitigate | This IS the threat the job is designed to detect. The gate runs `task gen` (full codegen) and `git diff --exit-code`; any drift fails the job; PR cannot merge until contributor regenerates and commits. |
| T-02-IS-LOG | Information Disclosure via CI logs | Redocly lint may print spec details to logs | accept | Redocly lint outputs warnings/errors which include schema field names. The spec at `/openapi.yaml` is already public per D-45; lint output cannot leak more than the spec endpoint exposes. |
| T-02-BYP | Bypass via skipped codegen step | Contributor edits openapi.yaml but skips committing the regenerated files | mitigate | The drift gate detects this by running codegen and diffing — exactly the desired enforcement. CONTRACT-04 acceptance. |
| T-02-BYP-2 | Bypass via fake-codegen commit | Contributor commits `generated.ts` content that does not match `pnpm gen:api` output | mitigate | The drift gate re-runs the actual codegen in CI; comparing to the committed version detects forged output. Determinism (Plans 03 + 05) is the prerequisite — if codegen is non-deterministic, the gate also fails (which is the correct failure mode: surface non-determinism). |
</threat_model>
