## Gray Areas Discussed (4)

### Area 1: code mutability after create in v0.1

**Options presented:**
- Immutable (Recommended) — PATCH rejects code change; rename via dedicated v0.2 endpoint
- Mutable with cascade — Allow PATCH but cascade through join refs, channel.default_queue_id, etc.
- Mutable without cascade — Allow PATCH, leave old refs dangling

**User choice:** Immutable (Recommended).

**Locked as:** D04_1-02. Returns HTTP 422 `immutable_field` on mutation attempts. Rename support deferred to v0.2 via dedicated endpoint.

**Notes from discussion:** Aligns with the user's broader preference (per Phase 3 D-72 patterns) for separating contract surfaces from mutation surfaces — immutable identity + explicit rename endpoint is consistent with the rest of v0.1.

### Area 2: code format constraint

**Options presented:**
- Strict: `^[A-Z][A-Z0-9_]{0,63}$` (Recommended) — uppercase, 1-64 chars
- Lenient: alphanumeric + `_-.`, max 128
- Free-form text, 1-128

**User choice:** Option 1 BUT preferred lowercase.

**Locked as:** D04_1-03. Final regex: `^[a-z][a-z0-9_]{0,63}$` (lowercase variant). Examples in OpenAPI use `emp_001`, `skill_voice_tier1`, `queue_billing` (D04_1-04).

**Notes from discussion:** Lowercase chosen for grep-friendliness, shell-friendliness (no quoting), DSL-safety (no operator-clash characters). Postgres `lower()` indexes already exist on names; consistent case handling reduces cognitive overhead.

### Area 3: backfill strategy for existing rows

**Options presented:**
- Backfill `code = external_id` (Recommended) — reuse external_id as initial code via lowercase + sanitize
- Drop table and recreate (clean slate) — `task db:reset`
- Backfill with UUID-suffix fallback — `code = external_id` else `'AUTO_' || substr(id,1,8)`
- No backfill (no seed data exists) — assume CI-reset on every run

**User choice:** Backfill `code = external_id` (Recommended).

**Locked as:** D04_1-10. Migration UPDATE statements sanitize: `lower(regexp_replace(input, '[^a-zA-Z0-9_]', '_', 'g'))` before NOT NULL is enforced. Adapter + break_reasons (no external_id) derive from `name` + UUID-suffix. Collision handling via `row_number() OVER (PARTITION BY org_id, code)` (D04_1-11).

**Notes from discussion:** Phase 3 just shipped — most likely no prod data; backfill is mostly for CI seed data + local dev rows. Migration safety completeness; collision smoke test included in plan Wave 1.
