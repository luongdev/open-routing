<decisions>
## Implementation Decisions

### Code Field Semantics (Area 1)

- **D04_1-01:** **`code` is a universal user-facing canonical identifier.** Required (`TEXT NOT NULL`) on every primary catalog entity. Composite `UNIQUE (org_id, code)`. Owned by the Open Routing user/operator. Used as the upsert key for Phase 5 bulk import, the cross-reference target for nested relationships (agent→skill, channel→queue), and the addressable identity in OpenAPI Import schemas. Future v0.2 DSL will reference catalog rows by `code` as well.
- **D04_1-02:** **`code` is immutable post-create in v0.1.** PATCH requests containing a `code` field that differs from the persisted value return HTTP 422 with `ErrorCode=immutable_field` and `field=code` in the response body. Rationale: code is the stable upsert/reference key — mutation introduces cascade ambiguity (audit logs, DSL refs, import templates). Rename support deferred to v0.2 via a dedicated rename endpoint that explicitly handles cascade semantics.
- **D04_1-03:** **`code` format: lowercase strict regex `^[a-z][a-z0-9_]{0,63}$`.** Letters, digits, underscores; must start with a letter; 1-64 chars. Lowercase only (chosen over uppercase per user preference 2026-05-17). Rationale: shell-friendly (no quoting), grep-friendly (case-sensitive search), DSL-safe (no symbols that would clash with future operator/quote syntax). Enforced at the handler layer (Layer 1 validation, returns 400 `invalid_body` if malformed). Not enforced via DB CHECK — handler is the single source of truth (mirrors agent_skills proficiency pattern D-74).
- **D04_1-04:** **Examples of valid `code` values.** `emp_001`, `skill_voice_tier1`, `queue_billing`, `channel_voice_primary`, `adapter_freeswitch_dc1`, `break_lunch`. Examples flow into OpenAPI `description` blocks and CSV templates.
- **D04_1-05:** **Empty `code` is invalid.** Cannot be the empty string. The NOT NULL constraint + handler validation reject it together. Migration backfill (D04_1-09) handles the empty-string edge case by deriving from `external_id` or `name`.

### `external_id` Demotion (Area 2)

- **D04_1-06:** **`external_id` becomes `TEXT NULL`.** All 6 entities. Partial unique index `(org_id, external_id) WHERE external_id IS NOT NULL`. Means an entity can exist with `code` only (hand-authored row) OR with both `code` and `external_id` (synced from external system). Two rows in the same org can both have NULL `external_id` without colliding.
- **D04_1-07:** **`external_id` is OPTIONAL on `Create*Request`, MUTABLE on `Update*Request`.** Unlike `code`, `external_id` is the field admins use to bind a catalog row to an external system after creation (or change the binding if the external system changes). Mutation is allowed; collision (changing to a value already in use within the same org) returns 409 `duplicate_external_id`.
- **D04_1-08:** **OpenAPI `external_id` description tightened.** Replace existing line at `openapi/openapi.yaml:288-292`:
  > Optional caller-assigned identifier from an external system (HR, CRM, etc.). Used for sync mapping only — NOT the upsert key for bulk import (use `code` for that). v0.1 supports at most one external source per entity per org; multi-source disambiguation deferred to v0.2 via `external_source TEXT`.

### Migration Strategy (Area 3)

- **D04_1-09:** **Amend `000002_catalog_v0_1.up.sql` in place per D-61.** No migration `003` created. The amended file does:
  1. For each of the 6 entity tables, in CREATE TABLE statement: add `code TEXT NOT NULL` column; change `external_id TEXT NOT NULL` → `external_id TEXT NULL`; replace `UNIQUE (org_id, external_id)` with `UNIQUE (org_id, code)` (full) + `CREATE UNIQUE INDEX ix_*_org_external_id ON tbl (org_id, external_id) WHERE external_id IS NOT NULL` (partial).
  2. For `adapters`: add both `code` (required) and `external_id` (optional) — table currently has neither.
  3. For `break_reasons`: add both `code` and `external_id`; DROP the existing `UNIQUE (org_id, name)` constraint and the `_org_id_name_key` index.
  4. Wire `code` into the partial functional name-search index where applicable (no-op — name search stays on `name`, not on `code`).
- **D04_1-10:** **Backfill in the same migration via UPDATE statements run BEFORE the NOT NULL is enforced.** For each entity:
  - 4 entities with existing `external_id NOT NULL`: `UPDATE tbl SET code = lower(regexp_replace(external_id, '[^a-zA-Z0-9_]', '_', 'g'))` BEFORE the column constraint flips.
  - `adapters`: `UPDATE adapters SET code = lower(regexp_replace(name, '[^a-zA-Z0-9_]', '_', 'g')) || '_' || substring(replace(id::text, '-', ''), 1, 8)` (name-derived prefix + UUID-suffix to guarantee uniqueness when multiple adapters share a name).
  - `break_reasons`: same pattern as adapters — name-derived + UUID-suffix.
  - Reality check: Phase 3 is freshly shipped and likely has no production rows; the backfill mostly serves CI seed data and local-dev rows. The migration safety is for completeness; collisions are extremely unlikely at this size.
- **D04_1-11:** **Backfill collision handling.** If a backfilled `code` collides with another `code` in the same org (e.g., two skills with the same external_id post-lowercase-sanitize), the migration appends `_<i>` to the second occurrence using a window function `row_number() OVER (PARTITION BY org_id, code)`. Plans Wave 1 includes a smoke test that runs the migration twice on identical seed data to verify no duplicate-key panic.
- **D04_1-12:** **Migration `000002_catalog_v0_1.down.sql` updated symmetrically.** Drops `code` columns; restores `external_id NOT NULL` and `UNIQUE (org_id, external_id)` constraints; restores `break_reasons.UNIQUE(org_id, name)`. The down migration is for completeness; v0.1 still runs `task db:reset` for testing rather than down-up cycles (D-25 carry-forward).

### OpenAPI Contract Updates (Area 4)

- **D04_1-13:** **6 entity schemas (`Agent`, `Skill`, `Queue`, `Channel`, `Adapter`, `BreakReason`) and 6 `*ListItem` schemas gain `code: { type: string, pattern: '^[a-z][a-z0-9_]{0,63}$' }` as required.** `external_id: { type: string, nullable: true }` (was: required string). Position `code` AFTER `org_id` and BEFORE `external_id` in the property order for readability.
- **D04_1-14:** **6 `Create*Request` schemas: `code` required, `external_id` optional.** Example payload (`CreateAgentRequest`):
  ```yaml
  required: [code, name, email]
  properties:
    code:
      type: string
      pattern: '^[a-z][a-z0-9_]{0,63}$'
      example: 'emp_0042'
    external_id:
      type: string
      nullable: true
      example: 'HR-EMP-0042'
  ```
- **D04_1-15:** **6 `Update*Request` schemas: `code` field present but MUST equal stored value (handler enforces).** Documented in the description: "code is immutable — passing a different value returns HTTP 422 with `ErrorCode=immutable_field`. To preserve backwards-compat with PATCH idiom, the field is accepted but checked." Rationale: keeps Update*Request shape symmetrical with Create*Request; handler enforces the immutability rule (Layer 2 validation).
- **D04_1-16:** **Error responses extended.** Existing `Duplicate external_id within the org.` (409) responses split into:
  - 409 `duplicate_code`: "An entity with this `code` already exists in the org. Use a different code or update the existing entity by ID."
  - 409 `duplicate_external_id`: "This `external_id` is already bound to another entity in the org. Update that entity's `external_id` first or omit the field."
  - 422 `immutable_field` (new): "`code` cannot be changed after creation. Use the rename endpoint (v0.2) or recreate the entity with the desired code." (Returns 422 not 409 because the request is well-formed and unique-key-valid; it's a business-rule rejection.)
- **D04_1-17:** **OpenAPI `description` blocks reference `.planning/phases/03-catalog-crud-go/03-CATALOG-IDENTITY-REVIEW.md` + `RESPONSE.md` for design rationale** under the spec-level `info.description` (one-line link), so future maintainers see why the contract has this shape.

### sqlc + Handler Updates (Area 5)

- **D04_1-18:** **Per-entity queries authored in `services/api/internal/storage/sqlc/queries/`.** For each of the 6 entities:
  - `InsertX`: add `code` to INSERT column list and RETURNING clause.
  - `UpdateX`: take `id, version, name, ..., external_id` (NO `code` — immutable); RETURN updated row.
  - `GetXByID`: add `code` to SELECT.
  - `GetXByCode` (NEW): `SELECT * FROM tbl WHERE org_id = $1 AND code = $2` (for Phase 5 upsert lookup).
  - `UpsertXByCode` (NEW, AUTHORED but not invoked by Phase 04.1 handlers): `INSERT INTO tbl (...) VALUES (...) ON CONFLICT (org_id, code) DO UPDATE SET ... RETURNING *`. Phase 5 plan-phase consumes this.
  - `ListX`: add `code` to SELECT.
- **D04_1-19:** **Handler validation layer 1 (oapi-codegen-generated):** Format check via OpenAPI `pattern` regex. Malformed code → 400 `invalid_body`.
- **D04_1-20:** **Handler validation layer 2 (entity-specific business rule):** Immutability check on PATCH. Sequence: (a) fetch existing row by `id`; (b) verify request `code` is absent OR equals stored `code`; (c) if differs → 422 `immutable_field`. Identical check pattern across all 6 handlers — extract to a shared `validateImmutableCode` helper in `services/api/internal/catalog/codecheck.go`.
- **D04_1-21:** **Handler error mapping:** orgDB `*pgconn.PgError` unique-violation 23505 → introspect `constraint_name`:
  - `..._org_id_code_key` → 409 `duplicate_code`
  - `ix_*_org_external_id` (partial unique) → 409 `duplicate_external_id`
  - Other 23505 → 500 (defensive — shouldn't happen).

## Specific Ideas

### Sanitization helper (migration backfill)

```sql
-- Reusable Postgres expression for migration backfill
-- Input: arbitrary string. Output: valid code per D04_1-03 regex
-- Example: 'HR-EMP-001!' → 'hr_emp_001_'
lower(regexp_replace(input, '[^a-zA-Z0-9_]', '_', 'g'))
```

For prefix safety (must start with letter):
```sql
-- If first char is not [a-z], prepend 'r_' (for "record")
CASE
  WHEN substring(input from 1 for 1) ~ '^[a-zA-Z]$' THEN lower(regexp_replace(input, '[^a-zA-Z0-9_]', '_', 'g'))
  ELSE 'r_' || lower(regexp_replace(input, '[^a-zA-Z0-9_]', '_', 'g'))
END
```

### `validateImmutableCode` helper signature (Go)

```go
// services/api/internal/catalog/codecheck.go
func validateImmutableCode(ctx context.Context, stored, requested string) error {
    if requested == "" || requested == stored {
        return nil
    }
    return errors.New("code is immutable; mutation not allowed in v0.1")
    // Caller maps this error to httputil.WriteError(w, r, 422, "immutable_field", "code")
}
```
