## Sampling Rate

- **After every task commit:** `cd services/api && go test -count=1 -short ./internal/catalog/...` (unit + handler tests, no testcontainer)
- **After every wave merge:** `cd services/api && go test -race -count=1 ./internal/catalog/... ./test/isolation/...` (full catalog + cross-org isolation)
- **Before `/gsd-verify-work`:** `task test && task lint && task gen && git diff --exit-code` — full CI mirror
- **Max feedback latency:** ~25 seconds per task

## Notes from Research (Validation-relevant)

1. **`oapi-codegen v2` does NOT auto-enforce `pattern` regex.** D04_1-19 (CONTEXT.md) Layer 1 claim is incorrect. Handler MUST run `validateCodeFormat` explicitly. Tests validate handler-side enforcement, not generated-code enforcement. **Action:** planner amends D04_1-19 to "handler-side via `validateCodeFormat` (Pattern 2)".

2. **Existing `mapPgError` 23505 mapping is broken** (Phase 3 SIMPLICITY-REVIEW MED finding — always returns `external_id_collision`). Phase 04.1's `constraint_name` introspect (D04_1-21) fixes this as a side effect. **Action:** test the bug fix explicitly — add `TestCreateAgent_DuplicateCode_DistinctFrom_DuplicateExternalId` to assert the 409 ErrorCode strings differ.

3. **`CreateAdapter` has NO 409 response wired today** (no unique constraint pre-Phase-04.1). Phase 04.1 must ADD the 409 wire shape, not just modify existing. Test `TestCreateAdapter_DuplicateCode_Returns409_DuplicateCode` is fresh ground, not edit of existing.

4. **Existing fixtures use hyphens** (`ext-iso-a` etc.) which the new regex rejects. Fixture rewrite is not pure search/replace — it requires editorial work to pick valid codes. **Action:** planner schedules fixture-rewrite as a discrete task in Wave 3 with explicit acceptance criteria (no `[A-Z]` or `-` in any seed `code` value).
