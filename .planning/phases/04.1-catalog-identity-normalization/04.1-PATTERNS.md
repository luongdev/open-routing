**Backfill pattern (D04_1-10 + D04_1-11, RESEARCH §Pattern 4 lines 449-475):**

```sql
-- For agents/skills/queues/channels (pre-existing external_id NOT NULL):
-- Step 1: derive candidate code (handle digit-prefix per D04_1-03 strict regex).
UPDATE agents
SET code = CASE
    WHEN substring(external_id from 1 for 1) ~ '^[a-zA-Z]$'
        THEN lower(regexp_replace(external_id, '[^a-zA-Z0-9_]', '_', 'g'))
    ELSE 'r_' || lower(regexp_replace(external_id, '[^a-zA-Z0-9_]', '_', 'g'))
END
WHERE code IS NULL;

-- Step 2: dedupe collisions within (org_id, code) using row_number window.
-- Idempotent: re-running on deduped data is a no-op (every partition has rn=1).
WITH dups AS (
    SELECT id,
           row_number() OVER (PARTITION BY org_id, code ORDER BY created_at, id) AS rn
    FROM agents
)
UPDATE agents a
SET code = a.code || '_' || dups.rn::text
FROM dups
WHERE a.id = dups.id AND dups.rn > 1;

-- Step 3: enforce NOT NULL after every row has a value.
ALTER TABLE agents ALTER COLUMN code SET NOT NULL;
ALTER TABLE agents ADD CONSTRAINT agents_org_id_code_key UNIQUE (org_id, code);
```

For `adapters` / `break_reasons` (no pre-existing `external_id`), use `name` as the seed: `lower(regexp_replace(name, '[^a-zA-Z0-9_]', '_', 'g'))`. RESEARCH §Pattern 4 (lines 478-481) recommends bare name-derivation + row_number dedup over the UUID-suffix recipe in CONTEXT.md `<specifics>` for symmetry across all 6 entities.

**Reality check (per D04_1-10, A1, A2):** Phase 3 just shipped (2026-05-16) and there are no production rows. The backfill mostly serves CI seed data; collisions are extremely unlikely at this size. The backfill must still be correct because the migration runs in CI via `task db:reset` on every PR.

**Migration safety hazards (carry-forward from Phase 3):**
- **Hazard (RESEARCH Pitfall 5):** Local dev with an already-applied 000002 will silently use the old schema. The plan MUST include a clear "run `task db:reset` after pulling Phase 04.1" directive. CI uses fresh testcontainer so CI catches it.
- **Hazard (D04_1-11 smoke test):** New file `services/api/test/isolation/migration_idempotent_test.go` runs the up migration twice on identical seed data and asserts identical post-state. If the row_number dedup is missing, the second run will produce a different result (because the first run already deduped, so the second run's appended `_2` collides with the first run's `_2`).

```go
// codecheck.go — Layer 1 + Layer 2 validation helpers for the `code`
// field on every catalog entity (D04_1-03, D04_1-19, D04_1-20).
//
// Why this file exists:
//   - oapi-codegen v2 does NOT auto-enforce OpenAPI `pattern` regexes
//     in the strict-server runtime (RESEARCH Pitfall 1). The handler is
//     the single source of truth for code-format validation.
//   - Immutability is a business rule (D04_1-02) that cannot be expressed
//     in OpenAPI; it must compare a request field to the stored DB value.
//   - Both checks repeat across 6 entity handlers. Centralizing them keeps
//     the per-entity handler bodies readable and the regex compiles once
//     at package init.
package catalog

import "regexp"

// codeFormat is the canonical regex from D04_1-03: lowercase, starts
// with a letter, letters+digits+underscore only, 1-64 chars. Compiled
// once at package init (regexp.MustCompile panics on invalid pattern,
// surfacing config errors at startup rather than at first request).
var codeFormat = regexp.MustCompile(`^[a-z][a-z0-9_]{0,63}$`)

// validateCodeFormat returns true iff s matches D04_1-03 strict format.
// Empty string returns false (D04_1-05 — empty code is invalid).
// Handlers map false → 400 invalid_body / reason="invalid_code_format".
func validateCodeFormat(s string) bool {
    return codeFormat.MatchString(s)
}

// validateImmutableCode is the PATCH-only immutability gate (D04_1-20).
// Returns true iff requested is empty (the field was absent from the
// PATCH body) or equals stored. Handler maps false → 422 immutable_field
// / field="code". Empty `requested` means the PATCH did not touch the
// field; we accept it as no-op.
//
// Note: handlers MUST call validateCodeFormat(requested) BEFORE this so
// a malformed PATCH like `"code": "UPPER"` gets 400 invalid_body, not 422.
func validateImmutableCode(stored, requested string) bool {
    return requested == "" || requested == stored
}
```

**Hazard:** The regex literal is compiled once via package-init `regexp.MustCompile` (panics on invalid pattern at startup, NOT at first request — fail-fast). Go's `regexp` uses RE2 → no ReDoS risk on the bounded `{0,63}` quantifier (RESEARCH §Security Domain row 4).

**Hazard:** `validateImmutableCode` MUST NOT trim whitespace (RESEARCH Open Question #3 — strict validation gives clear feedback; auto-trim was rejected). Test `TestValidateCodeFormat_LeadingSpace_Returns400` locks this.
