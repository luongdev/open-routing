## Hazards for Plan 04 + 05

1. **Camelcase `Id`, not uppercase `ID`** — `api.ErrorCodeDuplicateExternalId` (lowercase d in `Id`). The verify gate locks this; Plans 04 + 05 must use this exact form. Hardcoding `ErrorCodeDuplicateExternalID` in handlers will fail compile.

2. **Layer 1 must fire BEFORE Layer 2 in PATCH handlers (Pitfall 4):**
   ```go
   if req.Body.Code != nil {
       if !validateCodeFormat(*req.Body.Code) {
           return 400 invalid_body / "invalid_code_format" // Layer 1 — regex
       }
       if !validateImmutableCode(stored.Code, *req.Body.Code) {
           return 422 immutable_field / "code"             // Layer 2 — DB compare
       }
   }
   ```
   Reverse the order and a malformed PATCH `"code": "UPPER"` returns 422 instead of the correct 400.

3. **mapPgError BUG is still present** (RESEARCH §Pitfall 3) — `internal/catalog/errors.go` currently maps every 23505 to `ErrorCodeVersionConflict` / `external_id_collision`. Plan 04 MUST replace this with constraint-name introspection (RESEARCH §Pattern 3) so the new `<table>_org_id_code_key` (→ 409 `duplicate_code`) and `ix_<table>_org_external_id` (→ 409 `duplicate_external_id`) cases produce the right wire shape. Without this fix, the Plan 05 tests `TestX_DuplicateCode_Returns409_DuplicateCode` will FAIL (they'll see `version_conflict` instead of `duplicate_code`).

4. **`break_reasons` no longer has `UNIQUE(org_id, name)`** (dropped by Plan 04.1-01). The pre-04.1 409 path `name_collision` no longer fires; Plan 04 must update the BreakReason handler to surface 409 `duplicate_code` instead (the new uniqueness constraint).

5. **`UpdateX` parameter list now includes `external_id`** for ALL 6 entities (adapters + break_reasons NEW gain it; the other 4 already had it as a sparse-PATCH parameter). Plan 04 handlers must include `external_id` in the COALESCE narg block, mirroring the pattern.

6. **`UpsertXByCode` is AUTHORED, not invoked.** Phase 04.1 does NOT call `UpsertXByCode` from any handler — these methods exist for Phase 5 to consume. Plan 04 must NOT add upsert call sites; the catalog endpoints stay Insert-OR-409.

7. **codegen idempotency is now a contract** — any future SQL or OpenAPI change MUST be followed by `task gen` and the CI codegen-drift gate (Plan 04.1-06) will fail any PR where `git diff` on `services/api/internal/api/`, `services/api/internal/db/generated/`, or `web/packages/ui/src/api/generated.ts` is non-empty after running `task gen`. Verified: a second `task gen` invocation produced zero diff.
