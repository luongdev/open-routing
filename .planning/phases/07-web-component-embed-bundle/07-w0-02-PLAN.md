<objective>
Define the Ember color palette (extracted from user-provided screenshots
2026-05-18) using Tailwind v4 `@theme` directives — the v3-Frankenstyle
way to configure design tokens. Alias existing `--or-color-*` tokens to
the new variables so the 42 unmigrated compound components keep
rendering during the per-component rollout.

**Why @theme (not Vite plugin customPalette like v2)**: Frankenstyle v3
sits on Tailwind v4. Tailwind v4's design-token system is CSS-native via
`@theme { --token: value; }` directives in your CSS file. No JS config
file, no Vite plugin option. Same result, simpler.

**Why alias old `--or-color-*` tokens**: 42 components reference these.
Aliasing means `--or-color-app-bg: var(--background)` — the component
reads the new value without code change. Per-component plans (W0.0-10
through W0.0-22) replace token references gradually; W0.0-30 migration
removes the compat layer at the end.

**Out of scope:**
- Building any component (downstream plans)
- Removing the compat layer (W0.0-30)
- Old or-light/or-dark/or-brand themes (keep as fallback)
</objective>
