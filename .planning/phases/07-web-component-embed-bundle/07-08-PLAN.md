NOTE on mock fetch: openapi-fetch accepts a custom `fetch` via the
createApiClient config (D-38). The cleanest path for unit tests would
be to pass `fetch: mockFetch` into createApiClient — but the embed
constructs its client internally. Alternatives:
1. `vi.spyOn(globalThis, 'fetch').mockImplementation(...)` (shown
   above — WARNING #8 — auto-restored by `vi.restoreAllMocks()` in
   afterEach even when a test fails mid-assertion).
2. Expose a test seam on OpenRoutingCatalog (private field for
   fetch override) — adds production surface, avoid.
Use option 1. Direct `globalThis.fetch = mockFn` followed by manual
restore in each test (the previous shape) is FRAGILE — a thrown
assertion stops execution before the restore line, leaving the mock
patched for the next test. vi.spyOn writes to the same property but
records the original via the Vitest mock registry; `vi.restoreAllMocks()`
walks the registry and reverses every spy regardless of throws.
