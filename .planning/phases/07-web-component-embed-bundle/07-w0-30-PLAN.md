<objective>
The last W0.0 plan — migrate all 42 compound components from Shoelace
to the new or-* primitives (built in W0.0-10 through W0.0-22), then
remove Shoelace as a dependency. Bring embed bundle size back under 70
KB gzipped.

**Why this is the last plan**: Each per-component primitive plan
(W0.0-10..22) builds the replacement BUT does NOT touch the existing
compound components. That isolation lets each plan ship atomically. This
migration plan does the search-and-replace across all 42 files in one
pass.

**Why one big migration plan (not per-component-migration plans)**: A
search-and-replace `<sl-button>` → `<or-button>` is mechanical. Splitting
it across 13 plans creates merge conflicts because compound components
use multiple primitives. Better to do all replacements in one commit,
verified by the existing test suite.

**Out of scope:**
- Building new components (those are W0.0-10..22)
- Visual redesign beyond what or-* primitives provide
- Updating components OUTSIDE packages/ui or apps/admin (e.g., embed entry — that's Wave 1+)
</objective>

<execution_context>
Phase 7 W0.0 final plan. Depends on ALL 13 component primitive plans.

## Mapping table (sl-* → or-* or uk-classes)

| Shoelace | Replacement | Notes |
|----------|-------------|-------|
| `<sl-button>` | `<or-button>` | variant + size props map directly |
| `<sl-input>` | `<or-input>` | helperText / errorText props match |
| `<sl-select>` | `<or-select>` | options prop OR slotted `<or-option>` |
| `<sl-card>` | `<or-card>` | header / footer slots match |
| `<sl-tag>` / `<sl-badge>` | `<or-badge>` | variant prop matches |
| `<sl-dialog>` | `<or-dialog>` | open prop reflects |
| `<sl-tab-group>` / `<sl-tab>` | `<or-tabs>` | tabs prop + active-tab |
| `<sl-icon>` | `<or-icon>` | name prop (lucide names — see icon-names.ts) |
| `<sl-switch>` | `<or-switch>` | checked prop reflects |
| `<sl-checkbox>` | `<or-checkbox>` | checked + indeterminate |
| `<sl-tooltip>` | `class="uk-tooltip"` attr | direct uk-* utility (skipped per user) |
| `<sl-dropdown>` + `<sl-menu>` | `<or-dropdown items=...>` | items array |
| `<sl-spinner>` | `<span class="uk-spinner">` | direct uk-class |
| `<sl-alert>` | `<div class="uk-alert uk-alert-{variant}">` | direct uk-class |

## Step 2: Per-file migration loop

For each .ts file in the files_modified list:

1. Open file.
2. Replace `<sl-X` → `<or-X` (or uk-class equivalent per mapping table).
3. Replace `</sl-X>` → `</or-X>`.
4. Update prop names:
   - `?disabled` → `?disabled` (same)
   - `?required` → `?required` (same)
   - `variant=` → `variant=` (same for or-button)
   - `size="medium"` → `size="md"` (Shoelace used "small/medium/large"; or-* uses "sm/md/lg")
   - `helper-text=` → `helper-text=` (same)
5. Update event names:
   - `@sl-change` → `@or-change`
   - `@sl-input` → `@or-input`
   - `@sl-blur` → `@or-change` (or-input fires or-change on blur)
   - `@sl-after-show` / `@sl-after-hide` → `@or-dialog-open` / `@or-dialog-close`
6. Update icon names per remapping table.
7. Update slots: Shoelace uses `slot="prefix"` / `slot="suffix"`; or-input uses same names → no change.
8. Remove any Shoelace-specific imports at the top of the file.
9. Run the file's existing test(s) — must pass.

Repeat for all files in files_modified.
